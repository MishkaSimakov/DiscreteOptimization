# Задача коммивояжёра

## Решение 1

Я начал с того, что реализовал простейший 2-opt. Он получает на вход решение. Для каждого ребра в этом решении он
пытается применить 2-opt. 2-opt предполагает выбор двух рёбер, поэтому нужно выбрать ещё одно ребро. Для каждой вершины
я храню небольшой список потенциальных кандидатов (сейчас это 5 самых ближних вершин) и перебираю рёбра, смежные с этими
кандидатами. Если перебор завершился и улучшение не было найдено, то алгоритм завершается. Если же было найдено
улучшение, то оно сразу применяется, и перебор запускается заново.

Это решение взяло все простые пороги, кроме одного.
Подробнее [тут](https://github.com/MishkaSimakov/DiscreteOptimization/actions/runs/23863439498).

## Решение 2

Я начал реализовывать генетический алгоритм из статьи с семинара, но вместо Л-К я поставил 2-opt из предыдущего решения.
Я пробовал подбирать параметры, поставил вероятность мутации 0.2 и размер популяции 50. Изначально обходы генерируются с
помощью жадного алгоритма, но в простой реализации на последней задаче жадный алгоритм работает слишком долго (порядка 6
минут на 50 запусков), поэтому далее нужно будет как-то его оптимизировать. На всех задачах, кроме последней это решение взяло все пороги ([тык](https://github.com/MishkaSimakov/DiscreteOptimization/actions/runs/23890595857))

## Решение 3

После решения facility я решил серьёзно подойти к вопросу создания единого фреймворка для отжига. Я реализовал его в `src/common/annealing`. Он позволяет реализовывать разные стратегии изменения температуры, автоматически подстраивает число шагов при каждой температуре в зависимости от оставшегося времени, а также считает всякие метрики. Ещё фреймворк изолирует отдельные действия. Каждое из них реализовано в виде отдельного класса (пример в `src/tsp/solvers/annealing/TwoOptAction.h`). Этот класс описывает как генерировать этот тип действий, как оценить их gain, и как применить их.

Ещё я не знал как выбирать начальную температуру. Для этого я добавил функцию `estimate_start_temperature` в `src/common/annealing/SimulatedAnnealing.h`. Она случайно генерирует какое-то большое количество действий и оценивает их gain (то есть изменение целевой функции). Затем с помощью бинарного поиска находится такое значение температуры, при котором средняя вероятность принятия действий (среди семплированных) составит `desired_rate` (это параметр алгоритма). В решении я использовал `desired_rate = 0.3`.

Я применил этот фреймворк для этой задачи. Код решения лежит в `src/tsp/solvers/annealing`. Отжиг в данном случае применяет один тип действий: 2-opt. Первая вершина для 2-opt выбирается равновероятно, а вторая равновероятно среди 5 ближайших вершин к первой. Температура изменяется по правилу `src/common/annealing/GeometricCooling.h`.

Всё это вместе дало хорошие результаты: код взял все пороги. Файлы и результаты можно найти [тут](https://github.com/MishkaSimakov/DiscreteOptimization/actions/runs/25259222154).
